Deployment handover

VendorConnect Server Map

Two Node processes behind one Nginx domain, plus MongoDB. Everything below is what you need to stand it up; nothing else in the repo is required at runtime.

Stack Next.js 16 · Express 5 · Socket.io · MongoDB 7 Runtime Node 22 · PM2 Target OS Ubuntu 22.04 / 24.04

Request flow

Processes to keep alive

All defined in deploy/ecosystem.config.js — start both with one PM2 command.
PM2 appRunsPortNotes
vendorconnect-web Next.js production server from repo root 3000 Needs npm run build to have run first
vendorconnect-api backend/server.js — REST + Socket.io 5000 Fork mode, single instance. Cluster mode breaks sockets without a sticky adapter
mongod systemd service, not PM2 27017 Local install or a managed URI — either way, set MONGO_URI
nginx systemd service, config in deploy/nginx.conf 80 / 443 Certbot fills in the TLS block

First-time setup

  1. Bootstrap the box

    The script installs Node 22, PM2, Nginx, Certbot and MongoDB 7, and locks the firewall to SSH/80/443. Run it as a sudo-capable user, not root.

    bash deploy/setup-server.sh

  2. Write the two env files

    They are separate and both required. backend/.env holds every secret; the root .env only needs the API URL, and it is read at build time — set it before step 3 or the frontend will call localhost.

    backend/.env   # copy backend/.env.example, then fill in the table below
.env           # NEXT_PUBLIC_API_URL=https://your.domain.com/api

  3. Install and build

    npm ci && npm run build      # frontend
cd backend && npm ci && cd ..  # API

  4. Put Nginx in front

    Copy the config, set server_name, drop the default site, then let Certbot issue the certificate.

    sudo cp deploy/nginx.conf /etc/nginx/sites-available/vendorconnect
sudo ln -s /etc/nginx/sites-available/vendorconnect /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d your.domain.com

  5. Start both processes

    pm2 start deploy/ecosystem.config.js
pm2 save        # survives reboot

  6. Seed the first operator

    There is no self-signup for the platform console — this command creates the only account that can log in at /platform and configure tenants and SAP.

    cd backend
npm run seed:platform-admin -- --email you@example.com --name "Your Name"

  7. Verify

    /api/health reports API, MongoDB and live socket count. All three should answer 200 through the domain, not just on localhost.

    curl https://your.domain.com/api/health
curl https://your.domain.com/api/status

Backend environment

Full reference is backend/.env.example. These are the values that must be real in production — the server refuses to start on several of them.

NODE_ENV
production
PORT
5000 — must match the Nginx upstream
MONGO_URI
Local mongodb://127.0.0.1:27017/… or an Atlas string
FRONTEND_URL
Public HTTPS origin
ALLOWED_ORIGINS
Same origin, comma-separated. Wrong values break CORS and sockets
JWT_SECRET
Strong random string. Rotating it logs everyone out
MASTER_KEY
Encrypts stored SAP credentials and MFA secrets. Losing it makes them unrecoverable — back it up outside the box
MAIL_TRANSPORT
smtp in production; log only swallows mail
SMTP_* / MAIL_FROM
Real relay — invitations and password resets depend on it
SAP_MOCK_MODE
Leave true for launch
UPLOAD_DIR / MAX_FILE_SIZE_MB
./uploads, 10 MB. Nginx allows 15 MB for headroom
LOG_LEVEL
info

Things that will bite

  • buildThe frontend must be built before PM2 starts it. next start on an unbuilt tree fails immediately.
  • envThe API reads backend/.env, not the root one. Two files, two purposes — and NEXT_PUBLIC_API_URL is baked into the build, so changing it means rebuilding.
  • socketsKeep the /socket.io/ upgrade headers and the long read timeout. Without them connections die silently at Nginx's 60-second default.
  • socketsNever switch the API to PM2 cluster mode unless a sticky-session adapter is added first.
  • dataThis is multi-tenant. Nearly every collection is scoped by clientId — don't hand-edit documents in Mongo without knowing the tenant boundary.
  • filesbackend/uploads/ must be writable by the API process and included in whatever you back up; documents live on disk, metadata lives in Mongo.
  • dbKeep MongoDB on loopback. Confirm bindIp 127.0.0.1 in /etc/mongod.conf; 27017 is never open publicly.

Redeploys and day-two

Ship an update

Pulls, reinstalls, rebuilds and reloads both processes.

bash deploy/deploy.sh master

Where to look when it breaks

pm2 logs vendorconnect-api
pm2 logs vendorconnect-web
backend/logs/            # winston, rotated
GET /api/platform/health # SAP + subsystem detail

SAP call history is kept in Mongo as SapLog and expires after 30 days. Runbooks for backup/restore, key rotation, SAP outage and incident response are in docs/runbooks/.
